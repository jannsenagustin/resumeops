6. DOCKER COMPOSE DESIGN
------------------------

Services:

- atlas-search-head
- atlas-indexer
- atlas-deployment-server

Dedicated network:

- atlas-network

Persistent named volumes:

- atlas-search-head-var
- atlas-search-head-etc
- atlas-indexer-var
- atlas-indexer-etc
- atlas-deployment-server-var
- atlas-deployment-server-etc

Only the three Splunk Web interfaces are published to the Windows host.
Host mappings are restricted to 127.0.0.1.

Splunk management communication remains internal to atlas-network.

The future Indexer receiving port is represented for Sprint 6C planning but
receiving has not been enabled.

No Universal Forwarder or Linux log-source container was added in Sprint 6B.


7. ROLE RESPONSIBILITIES
------------------------

Search Head:

- Intended user search interface
- Future dashboards, reports, alerts, and knowledge objects
- Initial Monitoring Console location
- Future distributed searches against the Indexer

Indexer:

- Future forwarded-data receiver
- Event parsing and indexing
- Persistent event storage
- Distributed-search peer

Deployment Server:

- Future Universal Forwarder configuration management
- Future deployment-app distribution
- Future server-class management

The Deployment Server does not manage the Search Head or Indexer.
No fake Universal Forwarder client was created.


8. IMAGE AND VERSION STRATEGY
-----------------------------

The image repository is configured through:

SPLUNK_IMAGE=splunk/splunk

The image tag remains an explicit blocking placeholder:

SPLUNK_VERSION=VERIFY_SUPPORTED_TAG

The latest tag is not used silently.

A supported tag must be selected from official Splunk sources before
deployment.


9. PORT STRATEGY
----------------

Verified internal Splunk defaults used in the design:

- Splunk Web: TCP 8000
- Splunk management/API: TCP 8089
- Conventional forwarder receiving: TCP 9997

Proposed localhost Web mappings:

- Search Head: 127.0.0.1:8000
- Indexer: 127.0.0.1:8001
- Deployment Server: 127.0.0.1:8002

The proposed host ports may be changed in the local .env file if a collision
exists.

Management and receiving ports are not published to the Windows host in the
initial Compose design.
