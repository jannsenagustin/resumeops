# Atlas Engineering Console Component Roadmap

This roadmap sequences the planned visual evolution. Its statuses describe
design direction only, not implementation state. No phase listed here should
be read as an existing component, route, style, layout, or shipped feature.

## Status Definitions

| Status | Meaning |
| --- | --- |
| Approved | The visual direction is approved; implementation still requires phase approval and validation |
| Planned | The direction is defined for a later reviewed implementation phase |
| Future | The direction is intentionally deferred and remains subject to later design review |

## Phase 01 — Visual Foundation

**Status: Approved**

Establish typography, semantic colors, spacing, borders, panels, layout rhythm,
and shared state language. This phase should translate the approved principles
into implementation foundations without changing canonical content ownership.

## Phase 02 — Atlas Engineering Console

**Status: Planned**

Evolve the Atlas entry experience into a coherent engineering console organized
around current state, records, evidence, and system understanding.

## Phase 03 — Status Bar

**Status: Planned**

Provide a concise, factual system-state summary using canonical status data and
accessible semantic labels.

## Phase 04 — Pipeline

**Status: Planned**

Represent the engineering sequence and transitions between validated, planned,
and future work without manufacturing progress or activity.

## Phase 05 — Milestone Console

**Status: Planned**

Improve milestone discovery and inspection while preserving chronology,
canonical milestone boundaries, and the distinction between summary and record.

## Phase 06 — Evidence Console

**Status: Planned**

Make claim-to-evidence relationships easier to inspect while retaining evidence
context, validation meaning, and canonical file ownership.

## Phase 07 — Resume Experience

**Status: Future**

Connect the resume-level summary to relevant engineering records without
turning Atlas into a portfolio or duplicating canonical content.

## Phase 08 — Engineering Activity Log

**Status: Future**

Explore a factual chronology derived from real engineering records. Do not
simulate activity, invent events, or treat repository noise as progress.

## Phase 09 — Repository Experience

**Status: Future**

Improve the path from console context to reviewable source, configuration,
history, and records while respecting repository and DEA responsibilities.

## Implementation Gate

The [vision](VISION.md), [design principles](design-principles.md), and
[approved visual reference](images/atlas-engineering-console-visual-reference-v1.png)
govern every phase. A phase begins only after human approval. Completion must be
recorded by its implementation and validation work, not by this roadmap.
