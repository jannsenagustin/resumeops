# Contributing to Atlas

Atlas is an engineering project. Every contribution should improve the quality, traceability, and educational value of the repository.

## Engineering Principles

- Build incrementally.
- Document significant engineering decisions.
- Evidence should support engineering claims.
- Keep Git history meaningful.
- Prefer clarity over cleverness.
- Keep the repository organized as it evolves.

## Documentation Standards

Every major milestone should include, when applicable:

- Documentation
- Supporting screenshots
- Architecture updates
- Engineering notes
- Git commit

## Git Commit Convention

Use Conventional Commits.

- `chore:` Repository maintenance
- `docs:` Documentation only
- `feat:` New engineering capability
- `fix:` Bug fixes
- `refactor:` Internal restructuring
- `test:` Validation and testing

## Repository Philosophy

Atlas should evolve naturally.

Do not create folders "just in case."

New directories should only be introduced when they become necessary for the engineering work.

## Engineering Evidence

Evidence belongs inside `screenshots/`.

Evidence should demonstrate:

- Deployment
- Validation
- Troubleshooting
- Dashboards
- Architecture
- Engineering milestones

Evidence is not documentation.

Documentation explains the engineering.

Evidence proves it.
