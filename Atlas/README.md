# Atlas

> Atlas is an enterprise-style observability engineering project built to demonstrate real-world Splunk architecture, deployment, data ingestion, detection engineering, troubleshooting, and operational practices.

## Repository Philosophy

Atlas is treated as an engineering project rather than a collection of configuration files.

Every significant engineering milestone should be supported by:

- Implementation
- Documentation
- Engineering evidence
- Meaningful Git history

The repository should evolve alongside the project.

Avoid speculative folders and unnecessary scaffolding.

New structure should only be introduced when justified by the engineering work.

## Engineering Workflow

For each sprint, follow this workflow:

1. Design
2. Implement
3. Validate
4. Capture Evidence
5. Document
6. Commit

The Git history should tell the complete engineering story of Atlas from workstation setup through production-quality observability scenarios.

## Project Vision

Atlas will grow into a documented, enterprise-style observability platform and engineering case study.

## Repository Structure

- `assets/` stores visual source material.
- `compose/` holds future Compose deployment definitions.
- `docker/` holds future Docker build artifacts.
- `docs/` contains engineering documentation.
- `screenshots/` stores engineering evidence as a first-class project artifact.
- `scripts/` is reserved for future automation.
